## 二、需求 6 先单独回答：格式支持实测结果

这一条不需要开发就能回答，我在你的机器上逐项跑过：

### 阅读页面：✅ 支持

`page:read` 走的是「读文件 → 转 base64 → 交给 Chromium 解码」，Chromium 什么格式都能解。

实测你那个 webp 文件夹 `qqqpppqpqpqp\25.12.17 婊子女警`：

```
文件：1.webp
返回：ok=true, 750×1200, 110174 字节, mime=image/webp
画面：正常显示，与其他 JPG 无差别
```

GIF 同理，且**动图会真的动**——`<img>` 标签天然播放动图。

### 封面：❌ 不支持（已有 Bug）

封面走的是另一条路：主进程用 `nativeImage.createFromPath()` 解码后再缩小。
实测这个方法**认不出 webp 和 gif**：

| 格式 | nativeImage 结果 |
|---|---|
| PNG | ✅ 正常，8×8 |
| JPG | ✅ 正常，8×8 |
| WEBP | ❌ `isEmpty = true` |
| WEBP（带透明） | ❌ `isEmpty = true` |
| GIF（静态/动图） | ❌ `isEmpty = true` |

**实际后果**：你现在书架里那 74 个 `.webp` 文件夹（都在 `qqqpppqpqpqp` 下），封面全是灰色书本图标；点进去却能正常读。

### 修复方案（很小）

`cover:get` 遇到 `nativeImage` 解码失败时，不返回 `null`，改成直接返回原始 dataURL，让渲染层用 canvas 缩。canvas 走 Chromium 解码，webp/gif 都没问题。

- 改动点：`main.js` 的 `cover:get` handler，约 15 行
- 顺带好处：以后 PNG/JPG 封面也可以统一走这条兜底路径

### 两个要提醒你的副作用

1. **超大 GIF 会失去动画**：现有逻辑会把超过 4MB 的图降采样成静态 JPEG（`shrinkIfHuge`）。动图被拍平成一张静帧。
2. **长卷模式里多张动图会同时播放**：一屏几张 GIF 都在动，可能掉帧。如果遇到，可以加「动图只播当前页」的开关。

## 三、需求 1：启动不扫描

### 现状

`site/js/app.js` 第 52～64 行，每次启动只要配置里有根目录，就无条件 `await DB.scan()`。
`DB.scan()` 会触发 `main.js` 的 `scanRoot()`，把整个目录树递归走一遍。

你的 Pixiv 目录实际规模（我数过）：

```
目录深度分布：第0层 1 个，第1层 7 个，第2层 483 个，第3层 28 个
成书数：487 本
```

这就是每次进软件要等几秒的原因。

### 改法

1. 新增 `books.json`（存 `%APPDATA%\漫画阅读器\`，与 `progress.json` 同级），保存上次扫描结果。
2. `main.js` 增加两个 IPC：`library:cache-get` / `library:cache-set`。
3. `app.js` 启动流程改成：
   - 有缓存 → 直接读缓存渲染，**不扫描**，秒开
   - 没缓存（首次使用）→ 才扫描一次，扫完写缓存
   - 点「刷新」（`btn-refresh` / Ctrl+R）→ 扫描 + 更新缓存
   - 换文件夹（`chooseFolder`）→ 扫描 + 更新缓存
4. 书架显示一行小字：「列表来自上次扫描 · 最后更新 10-18 14:09」，让你知道数据的新鲜度。

### 取舍（需要你接受）

- 你在资源管理器里**新增或删除**了漫画，软件不会自动知道，直到你点刷新。
- 缓存文件很小（487 本约 120KB），可随 `progress.json` 一起备份。

## 四、需求 2：分层浏览（最大的一块）

### 现状

`main.js` 的 `scanRoot()` 是**一次递归到底**：进来就用 24 并发把整棵树走完，487 本书一次性全部算好再返回。
书架因此只能是一张平铺的大网格。

### 改法

新增 `browse(dir)` 接口，**只读一层**：

```
输入：D:\BaiduNetdiskDownload\Pixiv
输出：
  文件夹：[ {type:'dir', name:'成田大进', path:'...', hint:'89 项'}, ... 共 7 个 ]
  书籍：  [ {type:'book', ...} ]           ← 该层散落的 zip/pdf
  本层自身：[ {type:'book'} ]              ← 如果这个目录本身就是一本（只有图片）
```

界面：

- 根目录 → 显示 7 个文件夹卡片
- 双击 `成田大进` → 显示其中 89 个项目（这里都是书）
- 双击 `qqqpppqpqpqp` → 显示 121 个日期文件夹
- 双击某个日期文件夹 → 显示书
- 顶部加**面包屑导航**：`书架 › Pixiv › 成田大进`，点任一级可跳回
- 返回键 / Alt+← 也能回上一层

书（`type:'book'`）仍然**单击**打开；文件夹**双击**进入。

### 为什么这样能「不那么卡」

| | 现在 | 改后 |
|---|---|---|
| 进软件 | 遍历约 519 个目录 | 只读 1 个目录 |
| 进入某个作者 | 不适用（已在全局列表） | 只读 1 个目录 |
| 封面加载 | 488 张排队 | 只加载当前层可见的 |

### 三个必须先定的细节

**① 一个目录既有图片又有子文件夹，算不算书？**
现在的规则是「有子目录就不成书」，图片被忽略。分层后建议改成**双重身份**：既显示为可进入的文件夹，也显示为可打开的书。你的目录里确实存在这种情况（`qqqpppqpqpqp` 下 23 个日期文件夹，各自只有一个子目录里才有图）。

**② 还要不要「一次看全部 487 本」？**
分层浏览会让「找某一本」变难。两个选项：
- A. 严格分层，不提供全部视图（最省事，最不卡）
- B. 分层为主 + 加一个搜索框，搜索时后台做一次全量索引（体验好，但要额外做索引缓存）

**③ 排序功能怎么摆？**
「最近阅读」这种跨层排序在文件夹视图下没意义。建议：文件夹层固定按名称排；书层保留原来的三种排序。

## 五、需求 3：缩略图带移到进度条上方

### 现状

`style.css` 的 `.thumbs-panel` 是 `position:absolute; bottom:0`，直接贴在窗口底部，展开时**盖住**底部工具栏（进度条 + 模式按钮那一整条）。

所以现在是：点画面中部 → 缩略图带盖上来 → 工具栏被压在下面。

### 改法

把缩略图带**移进底部工具栏内部**，放在进度条那一行的上方。这样它天生就跟着工具栏一起升降：

```
┌──────────────────────────────┐
│  [缩略图 23] [24] [25] ...    │  ← 缩略图带（新增位置）
│  ●━━━━━━━━━━━━━━  12 / 2000   │  ← 进度条
│  [单页][跨页][条漫][长卷]  [☾][⛶] │  ← 工具按钮
└──────────────────────────────┘
```

交互按你的描述改：

- 左键点画面中部 → 工具栏 + 缩略图带**一起出现**
- 再点一次 → **一起隐藏**
- 点缩略图 → 跳页，工具栏保持显示
- Esc → 一起隐藏

### 涉及文件

`index.html`（把 `#thumbs-panel` 移到 `bar-bottom` 内）、`style.css`（改定位与动画）、`reader.js`（`showThumbs`/`hideThumbs`/`singleTap` 的联动）。

### 注意

现在缩略图带是从底部滑入的。挪进工具栏后，动画改成「工具栏整体从底部滑入」，内部不再单独做位移动画，否则会有两层动画打架。

## 六、需求 4：默认阅读方式 + Ctrl 循环四种

### 6.1 默认阅读方式

**现状**：打开一本书时 `S.mode = book.mode || 'paged'`，`book.mode` 来自这本书自己的阅读进度。新书永远从「单页」开始，所以你每换一本都要手动点一次。

**改法**：

1. `settings` 增加 `defaultMode: 'paged'`。
2. `openBook()`：这本书**没有历史进度**时，用 `settings.defaultMode`，而不是写死 `'paged'`。
3. 右上角加按钮（和现有的 `rd-more`、`rd-fullscreen` 排在一起），点开是一列四选一：

```
默认阅读方式
  ● 单页
  ○ 跨页
  ○ 条漫
  ○ 长卷
```

选中即保存到 `settings.defaultMode`，**之后所有新书都按这个开**。已有进度的书仍然接着上次的模式读，不被打断。

**需要你定**：这个按钮放**书架右上角**（和刷新、排序放一起），还是放**阅读器右上角**（读书时随手改）？我倾向阅读器右上角，因为你在读书时才最清楚想要哪个模式。也可以两处都放。

### 6.2 Ctrl 循环四种

**现状**：`toggleSpread()` 只在「单页 ↔ 跨页」之间来回跳，且如果当前是条漫/长卷，直接 `return`，没反应。就是你说的「ctrl 只控制改变单页和跨页」。

**改法**：改成 `cycleMode()`，按 `单页 → 跨页 → 条漫 → 长卷 → 单页` 循环。按一次换一个，顶部弹一个小提示（现在已有 toast 机制）。

**一个必须提醒的性能问题**：切到「长卷」要建全部页面占位（你那本 2000 页的会建 2000 个格子）。用 Ctrl 快速连按循环时，可能会卡一下。两个缓解办法：
- 只建前 400 页，滚动到再补（现有代码已有这个分批逻辑，确认一下是否生效）
- Ctrl 循环时跳过「长卷」，只循环前三种

我建议先做完整四循环，实测卡顿程度再决定要不要加限制。

## 七、需求 5：自定义封面

### 改法

1. `settings` 增加 `covers: { 书籍id: 图片绝对路径 }`。
2. 书架卡片右键菜单（`showBookMenu`）增加两项：
   - 「设置封面…」→ 弹出选图对话框（jpg/png/webp/gif 都行），选中后写入 `covers`
   - 「恢复默认封面」→ 删掉该条记录，回到「目录第一张图」
3. `cover:get` 逻辑改为：有自定义路径且文件存在 → 用它；否则用原来的第一张图。
4. 自定义封面同样缩到 200px 再进书架。

### 细节

- 只改「显示用的封面」，**绝不移动、复制或改动你的图片文件**，只记一个路径。
- 如果自定义的图片被你删了 → 自动回退到默认封面，不报错。
- 封面选择器要能读 webp/gif（依赖需求 6 的修复）。

## 八、实施顺序建议

按「风险从低到高、收益从快到慢」排：

```
阶段 A  ── 立刻见效，改动很小
  ⑥ 封面支持 webp/gif          ~15 行
  ④ 默认阅读方式 + Ctrl 四循环   ~60 行
  ③ 缩略图带挪到进度条上方       ~40 行（含 HTML/CSS 结构调整）

阶段 B  ── 独立功能
  ⑤ 自定义封面                  ~90 行

阶段 C  ── 书架改造
  ① 启动不扫描（缓存）           ~70 行
  ② 分层浏览                    ~400 行（重构，最大）

每个阶段做完都：语法检查 → 启动实测 → 跑 verify-all.js → git 提交
```

**为什么 ① 排在 ② 前面**：① 独立、改动小，做完你马上就能少等几秒；② 是书架重构，做完后 ① 的缓存逻辑还要跟着调整一次。如果你不介意多等一轮，也可以先做 ②——分层浏览做完后，启动只需读一层目录（毫秒级），① 几乎就是白送的。

**开工前我会做的两件事**（需要你同意）：
1. `git commit` 一次当前状态（虽然工作区已经干净，但确认基线）
2. 在项目目录**之外**打一个带日期的 zip 备份 —— 上次误删的教训，目前项目仍然只有 git 存档、且 `.git` 与源码同盘同目录
